# Testing

```bash
bash tests/fleet_guard/run_tests.sh            # last line: RESULT: 200 passed, 0 failed; exit status 0, and 1 when any check fails
```

The suite runs on any machine with bash, Python and git: no scheduler, no GPU, no network.

## How it works

`run_tests.sh` copies the `slurm/` tools into a temporary folder with a test site file (`site.test.env`: a four-node fleet with a review threshold of 50 GPU-hours) and test caps (`caps.test.json`). It puts fake `squeue`, `sbatch`, `scontrol` and `sacct` (in `tests/fleet_guard/bin/`) first on `PATH`. The fakes keep a job table in a state file, record every `sbatch`, `scontrol` and `sacct` call, and can be told to fail (`squeue_fail`, `sacct_fail`, `sbatch_fail` marker files) or to answer slowly once (`sacct_slow`); `squeue -r` lists a collapsed pending array one task a line, `sbatch --array` writes the pending array as the one compressed row `squeue` shows, and every `squeue` call is logged with its task-list setting (`SLURM_BITSTR_LEN`). Nothing can reach a real scheduler, and no live queue, lock, log or caps file is touched.

`test_watchdog.sh` drives `pack_node.py` in fake mode with `PACK_FAKE_GPU_UTIL` set, so every fake GPU reports the utilisation the test chooses: idle long enough ends the job with the right receipt; active does not; a zero window disables it. Then readings that differ by slot: one slot idle and one never read (not idle: the review's case), a slot that GPM misses read by `nvidia-smi` instead (idle, then busy), a NaN reading, and one value per fake slot.

`test_login_check.sh` runs `tools/login_check.py` on whatever machine runs the suite: a verdict whose exit code matches it, as many cores as workers, WAIT with no cores when the memory asked for cannot fit or every core is excluded, and nothing written. A fake `nvidia-smi` then shows the login GPU's rule counting what you hold already: 10 GiB held and 10 more is over 16, 4 more is not. The other process on the fake card has a PID that cannot exist, so it counts as someone else's whoever runs the suite, root included.

`test_ffscoped.sh` builds a bare origin, a shared clone and an outside clone that pushes edits, a deletion that empties a folder, a mode change, retargeted and new symlinks, a path with spaces and a non-ASCII name. It then checks a clean run, the dry run, a local edit, a staged change, an untracked file in the way, an unpushed lane commit, both forms of the race the tool exists for, a held lock, and that a lane's staged work elsewhere survives. Then the writers the tool must never overwrite: a file changed after the check and before the files are written (the review's reproduction, through a git wrapper that pauses there), the same for a file origin deletes and one it adds, a file recreated between its move aside and the new version, a write into a moved-aside file, a file written moments before the run, the dry run's list, the backups kept and pruned, and a folder on a changed path replaced by a symbolic link to one outside the checkout, refused with nothing written.

`test_launcher.sh` runs the launcher in fake mode and sends it `SIGUSR1` while a checkpoint-aware program saves for two seconds. As a single command and as a compound one (`program; echo post`), the launcher waits for the save and the receipt reads a checkpoint segment; a program that does not handle the signal dies of it (exit 138) and nothing after it runs. A program started with `&` and waited for (`program & wait $!`) has its save counted; without a handler, that form still fails; and a background save beside a foreground program that dies of the signal does not mask the failure. Each program announces itself only once it runs, so the signal never lands between commands. A task whose folder is missing is refused before anything starts; a start that fails after another task has started stops that task and leaves a receipt with `launch_error`. A spec that would leave a GPU idle is refused before anything starts, and runs with `--allow-partial` only beside a written `--reason`, which the receipt keeps; a CPU pool whose command file cannot be read is refused the same way.

`test_lanegit.sh` commits through `lanegit.sh` on a throwaway repository with the index lock held, edits the file again, and checks that the replayed index update records the committed version, so the newer edit stays a change that the next folder commit takes; then a staged change and a staged deletion, each taken by a folder commit; a deleted folder named by its own path, committed as removed, and a path that never existed, refused; and the pre-commit hook measuring a renamed file that grew. `push` runs against a throwaway origin: a plain push, the same push again (already on origin), a push from behind origin (a merge commit with both parents, local `main` and the working tree untouched), a conflict refused with origin unchanged, and a commit that is not on local `main`, or does not exist, refused. `check` reports the index lock and the staged entries by lane, and `index` replays a deferred update. The pre-push hook refuses a push whose commits carry a blob over the limit, naming its size in bytes, unless `FLEET_ALLOW_LARGE=1`. The hook installer, run twice from a folder inside a throwaway clone, sets `core.hooksPath` to the hooks' folder relative to the clone and makes both hooks executable; the installed pre-commit hook then refuses a file over the limit; outside any clone the installer stops on git's error.

**CI.** [`.github/workflows/tests.yml`](../.github/workflows/tests.yml) runs the suite on every push and pull request, and the run fails when any check fails. `probes/test_nccl_stop.py` (PyTorch on CPU, two processes) checks the NCCL probe's stopping rule and its parameter comparison; it is not part of the suite.

## Adding a guard

Every new guard comes with a check in this suite before it is released. Extend the fakes when a guard needs a new Slurm behaviour. Keep the failure mode in view: a test that only checks the success path is not enough, so test what the guard does when Slurm answers wrongly or not at all.
